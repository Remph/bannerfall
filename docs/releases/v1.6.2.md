A patch release on top of 1.6.1. The plan editor's Mines tile now adds one line for all three mines, a village link opens the map zoomed in on that village, the bars open their pages at the top, the village overview adds up the support from other villages, and there is a sixth colour theme with pure black pages for OLED screens. For hosts, `ops/bannerfall-auto-update` can install new patch releases by itself every night (optional). No database migration and nothing to configure.

## What is new and fixed

**Village automation**
- **Mines line:** the "Mines" tile in the plan editor adds one line, "all mines to level N", instead of three. The village builds whichever of woodcutter, clay pit and iron mine is lowest first, and the line is done when all three have reached the level. A plan code carries it as `MINES:N`. Plans saved before 1.6.2 work unchanged

**Village and map**
- **Village links zoom in:** a link to a village (from the rally point, a player's page or the farm list) opens the map zoomed in with that village outlined, instead of showing the whole map. The village's panel stays closed so it doesn't cover a phone screen
- **Support at a glance:** *Troops at home* on the village overview shows the support from other villages as a separate total

**Navigation**
- The entries of the bars (and the game's logo) open their page at the top, not at the scroll position the page had before

**Colour themes**
- A sixth theme, *Black and gold (OLED)*: pure black pages and map background in the dark, slightly lifted cards, the same gold accents as *Black and gold*, which it equals in the light. Pick it in Settings, Colours

## For hosts

- **No migration, nothing to configure.** No new settings or environment variables, no change to Caddy, `compose.prod.yaml` or `edge/`
- **Automatic patch updates (optional):** `ops/bannerfall-auto-update` in a nightly cron line installs the newest patch of the minor version the world runs (1.6.2 to 1.6.3, never to 1.7.0) with `ops/bannerfall-update`: backup, a five-minute warning in the chat, health check and the automatic rollback. It then moves the shared Caddy checkout to the same tag. A new minor or major version is only mentioned in its log. `touch auto-update.hold` pauses it, a version that failed is not tried again, and an optional free healthchecks.io address (`AUTO_UPDATE_PING_URL`) tells you about failures and about runs that didn't happen. `ops/bannerfall-auto-update --dry-run` shows what it would do. The script comes with the checkout, so update to 1.6.2 by hand first; `docs/hosting.md`, section 10, has the cron line and the details
- **API:** `GET` and `PUT /api/build-plans` carry a `mines` flag on a plan line; a missing flag reads as false. Nothing was removed
- Open pages reload by themselves when the server version changes (since 1.2.1)

## Upgrading a running world (from v1.6.1)

1. `git fetch --tags origin && git checkout v1.6.2`
2. `ops/bannerfall-update 1.6.2` (add `--build` if you build your images on the server). It takes the backup, warns the players, restarts a minute later and checks the new version. Only the app is recreated, and there is no migration
3. Several worlds behind the shared Caddy: update every world, then check out the same tag in the edge folder (`edge/` itself is unchanged)

Or by hand, as before: announce the update (`bannerfall-admin broadcast "Update in 5 minutes"`), take a backup (`ops/bannerfall-backup`), pull the image below or build it with `--build-arg VERSION=1.6.2`, set `BANNERFALL_IMAGE` in `.env` to it, `docker compose -f compose.prod.yaml up -d`, then check `bannerfall-admin status` (version 1.6.2) and `bannerfall-admin check`.

Going back to 1.6.1 is safe for the database, since there is no migration: set the old image and `git checkout v1.6.1`, then `up -d` again. One catch: 1.6.1 doesn't know the Mines line, so a plan that already got one stops its village's automation after a rollback until the plan is edited (the lines before it are not affected).
