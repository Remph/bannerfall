A patch release on top of 1.6.0. Village automation says why a unit is missing and refills lost units sooner, and a plan can be shared as a short code. The rally point's Incoming and Outgoing cards fold, a farm list can be copied to another village, and a few small things in the farm list, the night bonus and the admin page are tidier. For hosts, the backup script can ping a monitoring address. No database migration and nothing to configure.

## What is new and fixed

**Village automation**
- **Says what a unit needs:** a recruit template with a unit the world doesn't offer yet now reads "Swordsman (needs Smithy 1)" instead of just "missing"
- **Refills sooner:** when you open a village's automation status after it lost units, it looks again at once instead of waiting up to 30 minutes
- **Plan codes:** "Share as code" turns a plan into a short text (`BFP1|name|…`) you can send to a friend, and "Use a code" fills the plan editor from one. Nothing is saved until you press Save, and a code that doesn't fit the world is refused
- **Plan editor:** the reorder button sits below the lines, and a "Mines" tile adds the next level of clay pit, iron mine and the third mine in one go

**Rally point**
- The Incoming and Outgoing cards fold. Each device remembers which are folded, and a folded card still shows how many movements it holds and how many of them are hostile attacks. A link ending in `#incoming` or `#outgoing` opens the card

**Farm list**
- **Copy to another village:** the "…" menu of a farm list copies its entries to another of your villages. It only adds what the other list lacks, skips your own villages, stops at the 50-entry limit and tells you how many of each it did
- The arrow on each row sits next to its text again

**Smaller fixes**
- The night bonus labels and hint fit narrow screens (no overflow at 320 px)
- The admin page's World tab lists the economy cards in a better order: market, largest ratio, automation
- A few wordings are neutral where they named a gender

**Landing page:** the title on bannerfall.de fits a 320 px screen

## For hosts

- **No migration, nothing to configure.** No new settings or environment variables, no change to Caddy, `compose.prod.yaml` or `edge/`
- **Backup monitoring:** `ops/bannerfall-backup` accepts an optional `BACKUP_PING_URL`, for example a free healthchecks.io check. A good backup requests the address, a failed one requests it with `/fail` added, and you are mailed when neither arrives in time. Without the variable nothing changes. README and `docs/hosting.md` have an example
- **API:** `POST /api/villages/{id}/farm-targets/copy` is new and `GET /api/villages/{id}/automation` carries `blocked`; nothing was removed
- **Simulation test:** `NpcSimulationTest` stops cleanly when a world ends by victory and takes `-PsimSpeed`, `-PsimLords` and `-PsimSqlFile`
- Open pages reload by themselves when the server version changes (since 1.2.1)

## Upgrading a running world (from v1.6.0)

1. `git fetch --tags origin && git checkout v1.6.1`
2. `ops/bannerfall-update 1.6.1` (add `--build` if you build your images on the server). It takes the backup, warns the players, restarts a minute later and checks the new version. Only the app is recreated, and there is no migration
3. Several worlds behind the shared Caddy: update every world, then check out the same tag in the edge folder (`edge/` itself is unchanged)

Or by hand, as before: announce the update (`bannerfall-admin broadcast "Update in 5 minutes"`), take a backup (`ops/bannerfall-backup`), pull the image below or build it with `--build-arg VERSION=1.6.1`, set `BANNERFALL_IMAGE` in `.env` to it, `docker compose -f compose.prod.yaml up -d`, then check `bannerfall-admin status` (version 1.6.1) and `bannerfall-admin check`.

Going back to 1.6.0 is safe: there is no migration, so set the old image and `git checkout v1.6.0`, then `up -d` again.
