A patch release on top of 1.7.0 that cleans up the game's screens. Tutorial refunds no longer pile up as empty messages when the warehouse is full, the recruit screen puts Recruit first, and the Town Hall, the Smithy, the Banner Hall, the reports and the statistics are calmer and line up better on phones and desktops. No database migration and nothing to configure; besides the game's screens only dependencies were updated.

## What is new and fixed

**Tutorial**
- **Refunds with a full warehouse:** a tutorial refund that met a full warehouse showed an empty "Tutorial refund:" message, and up to four of them stacked over the village. The refunds of one step now come as one message, and a refund where nothing arrived says "Tutorial refund lost: the warehouse is full."

**Recruiting**
- **Recruit comes first:** "Dismiss" moved into each unit row's "…" menu, so it no longer looks stronger than Recruit. A row's own Recruit button shows once the row has a number (or a reason why it can't recruit); "Recruit all" stays the main button
- **Steady rows:** on wider screens the − / number / + controls have a fixed width, so they line up from row to row

**Buildings**
- **Town Hall:** on wider screens the costs sit in fixed cells (wood under wood), and every upgrade button has the same width, so the rows form even columns with or without a hint
- **Smithy and Banner Hall:** a unit's level shows as the quieter level badge, and the tables list only the current and the next level instead of every level
- **Banner Hall:** when one attack locks both the banner and the standard, a single line under the title explains it and each card shows a short "Locked" chip. The rules of the standard, the stash and the banner thieves are folded away under "How it works"

**Reports, statistics and navigation**
- **Reports:** the unread dot uses the accent colour; red stays for war and for the counts on the bars
- **Phone tab bar:** the rally point tab is called "Rally Point" ("Sammelplatz"), like its page, instead of "Troops", which read like the place to recruit
- **Statistics:** the read-out above a chart already names each line next to its colour, so the second legend under the chart is gone. On a world's first day the world statistics say once that the lines grow from tomorrow on, as a player's own chart does
- **Text sizes and switches:** the client uses one scale of text sizes instead of 27 separate ones (most text keeps its size; a few sizes moved by a few per cent), and every on/off switch is the same component, so they look and behave alike in the settings, push settings, automation, world setup and the admin page

## For hosts

- **No migration, nothing to configure.** No new settings or environment variables, no API change, no change to Caddy, `compose.prod.yaml` or `edge/`
- **Updated dependencies:** Spring Boot 4.1.2 (game server and account server), springdoc-openapi 3.2.0, Gradle 9.8.2, Node 24.22.2 in the image's build stage, and minor updates of TanStack Query, React Router and Vite. The API description now lists the admin cheat endpoints as `204 No Content`, which is what they always answered. The account server has the same Spring Boot update; rebuilding its image is optional
- **Automatic patch updates:** a world with `ops/bannerfall-auto-update` in its nightly cron line moves from 1.7.0 to 1.7.1 by itself once the image is published (backup, a five-minute warning, health check, rollback). `touch auto-update.hold` pauses it
- Open pages show the "Reload" strip for this patch and keep running until the player reloads

## Upgrading a running world (from v1.7.0)

1. `git fetch --tags origin && git checkout v1.7.1`
2. `ops/bannerfall-update 1.7.1` (add `--build` if you build your images on the server). It takes the backup, warns the players with a popup, restarts a minute later and checks the new version. Only the app is recreated, and there is no migration
3. Several worlds behind the shared Caddy: update every world, then check out the same tag in the edge folder (`edge/` itself is unchanged)

Or by hand, as before: announce the update (`bannerfall-admin broadcast "Update in 5 minutes"`), take a backup (`ops/bannerfall-backup`), pull the image below or build it with `--build-arg VERSION=1.7.1`, set `BANNERFALL_IMAGE` in `.env` to it, `docker compose -f compose.prod.yaml up -d`, then check `bannerfall-admin status` (version 1.7.1) and `bannerfall-admin check`.

Going back to 1.7.0 is safe, since there is no migration and nothing is stored differently: set the old image and `git checkout v1.7.0`, then `up -d` again.
