A patch release on top of 1.5.0 with small comforts and fixes for phones and desktops. The market's send form can pick one of your own villages as the target, "My profile" has its own entry in the menus, the menus light the page you are on, and an open report scrolls to its end on desktops. On narrow phones (320 px) the count fields of the market and the rally point and the recruit counts fit their cards again. Behind the scenes, NPC lords' rounds and the career reports got faster and sturdier, and more pages refresh by themselves. One small database migration (V48, an index) and nothing to configure.

## What is new and fixed

**Market**
- **Send to your own villages:** an "Own villages" button under the send form's target field opens a list of your other villages, nearest first, with the distance and the merchants' travel time. A tap fills in the target. With only one village the button is hidden
- **Live refresh:** the market follows a finished Market level by itself

**Menus**
- **My profile:** phones have a "My profile" tile first in the More sheet's Player group, desktops a row at the top of the gear menu
- **The open page lights up:** every page now lights its entry in the menus. Other players' profiles and the statistics light Ranking, another guild's page lights Guild, your own profile and the settings light the gear button on desktops and More on phones. The More tiles and the gear menu's rows mark the open page
- **Gear menu in a small window:** in a 700 px high window the gear menu no longer scrolls inside itself; the language and theme labels sit beside their switches

**Reports**
- **Scrolling to the end on desktops:** an open report now ends at the window's bottom, so its own scroll reaches the end ("Simulate this attack") without scrolling the whole page first

**Narrow phones (320 to 359 px)**
- **Count fields:** the − / count / + rows with their "max" chip were wider than the card in the market's send, own offer and exchange forms and at the rally point, and pushed the target field past the card's edge. The chip now takes a second line where the row doesn't fit, and the rally point's Support / Attack pair stacks. 360 px and wider are unchanged
- **Recruit counts:** "2,000 at home (2,000 total)" could run under the Dismiss button. The total now takes a second line only where both parts don't fit. The German "Schwertkämpfer" breaks at the compound when it has to

**Refreshing by itself**
- The Banner Hall's training follows new Banner Hall levels, catapult damage and a lost village; a lost or conquered village refreshes the map and the profiles

## For hosts

- **Migration V48** (schema 47 → 48): an index on `movement (owner_player_id, kind)`, which every farm send and NPC round looks movements up by. It only adds an index and takes moments on a world of today's size. Going back to 1.5.0 then needs the backup the update script takes (or dropping the index by hand)
- **NPC lords:** a lord's round counts the other lords' attacks in one database query instead of reading every lord's memory, so rounds no longer grow with the square of the number of lords
- **Career reports:** when the account server rejects a batch of career reports, the world sends it again one player at a time and records those it takes, so one rejected report no longer holds back every player after it
- **Settings check:** a test now migrates a fresh database and compares its world settings with the built-in defaults, so a column default can't switch a feature on unnoticed
- **Nothing to configure:** no new settings or environment variables, no changes to Caddy, `compose.prod.yaml` or `ops/`
- No API change. Web dependencies updated (React 19.3.1, STOMP 7.5, TanStack Query 5.104.3)
- Open pages reload by themselves when the server version changes (since 1.2.1)

## Upgrading a running world (from v1.5.0)

1. `git fetch --tags origin && git checkout v1.5.1`
2. `ops/bannerfall-update 1.5.1` (add `--build` if you build your images on the server). It takes the backup, warns the players, restarts a minute later, applies V48 and checks the new version. Only the app is recreated

Or by hand, as before: announce the update (`bannerfall-admin broadcast "Update in 5 minutes"`), take a backup (`ops/bannerfall-backup`), pull the image below or build it with `--build-arg VERSION=1.5.1`, set `BANNERFALL_IMAGE` in `.env` to it, `docker compose -f compose.prod.yaml up -d`, then check `bannerfall-admin status` (version 1.5.1) and `bannerfall-admin check`.

Going back to 1.5.0: restore the backup taken before the update, set the old image and `git checkout v1.5.0`, then `up -d` again.
