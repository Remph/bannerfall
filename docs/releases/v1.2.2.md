A patch release for the running playtest. Wood no longer runs out long before clay and iron, the report list and the farm list show where banners came from and which targets can still drop one, NPC lords stop sending a handful of scouts to certain death, and two small layout fixes. It builds on v1.2.1; existing worlds keep running and need no database migration.

## What is new

**Banners at a glance**
- **"New banner" tag in the report list:** a battle that gained the reader a banner (found in the battle, stolen by their banner thieves, or taken with a conquered village) shows a "New banner" pill with the small banner picture next to Won/Lost. It is worked out from the stored report, so older reports show it too
- **"Banner chance used" tag in the farm list:** while a player's daily banner chance against a target is used, its line shows "Banner chance used · back at 14:32", so one can aim for the targets that can still drop a banner. Against a player or NPC lord the chance counts per player, so the tag is on all of their villages; against barbarians it is per village. One line under the list explains it. Hidden on worlds without banners or without banner drops. The rules themselves are unchanged

**Balancing: less wood, more clay and iron**
- Before, about 41 % of what a village spent in the early game was wood (38 % in the mid game), while the three mines produce the same. Wood ran out first and clay and iron piled up
- Part of the wood price of six buildings and two units moved onto clay and iron. **Every total stays the same**, so nothing is cheaper or dearer overall. Demand is now about 36 / 35 / 29 % (wood / clay / iron) early and 34 / 32 / 33 % mid game
- Orders already in a queue keep what they paid

| | Before (wood / clay / iron) | Now |
|---|---|---|
| Town Hall | 90 / 80 / 70 | 80 / 85 / 75 |
| Barracks | 200 / 170 / 90 | 180 / 180 / 100 |
| Clay Pit | 65 / 50 / 40 | 55 / 55 / 45 |
| Iron Mine | 75 / 65 / 70 | 65 / 70 / 75 |
| Farm | 45 / 40 / 30 | 40 / 40 / 35 |
| Warehouse | 60 / 50 / 40 | 50 / 55 / 45 |
| Spearman | 50 / 30 / 10 | 40 / 35 / 15 |
| Axeman | 60 / 30 / 40 | 50 / 35 / 45 |
| Spearman level 2 / 3 research | 1000 / 600 / 200, 2500 / 1500 / 500 | 800 / 700 / 300, 2000 / 1750 / 750 |
| Axeman level 2 / 3 research | 1200 / 600 / 800, 3000 / 1500 / 2000 | 1000 / 700 / 900, 2500 / 1750 / 2250 |

For buildings these are the base prices; they grow with each level as before (same cost factors).

**NPC lords**
- An NPC lord that was scouted now remembers how many of the attacker's scouts went home, and only scouts back with at least twice that many plus one (as it already did for scouts it had seen). Without enough scouts it neither scouts nor retaliates, instead of sending a few scouts into a village it knew was full of them

**Layout**
- **Phone chat opens at the newest message** instead of the first one; it also stays at the end when the keyboard opens
- **The Banner Hall is listed between the Workshop and the Academy** in the village overview, the Town Hall, reports and the recruit tabs (Barracks, Stable, Workshop, Banner Hall, Academy). Only the display order changes
- The README has a header image

## For hosts

- **No database migration** (the schema stays at V30) and nothing to configure: no new settings, no new admin commands, no changes to Caddy, `compose.prod.yaml` or `ops/`. Going back to 1.2.1 only needs the old image
- **A ready-made server image** is built from every release tag from now on (the line to pull it is below). Pulling it replaces the `docker build` step of the hosting guide; checking out the tag is still needed for `compose.prod.yaml`, the `Caddyfile` and `ops/`. Always set the exact version in `BANNERFALL_IMAGE`, never `latest`
- API: report list items carry `summary.bannersGained` (`[{type, tier}]`); farm list targets carry `nextBannerRollAt` (null when the chance is free or banners are off). NPC lord memory has a new field that reads as 0 from older saves
- Open pages reload by themselves when the server version changes (since 1.2.1)

## Upgrading a running world (from v1.2.1)

1. Announce the update (`bannerfall-admin broadcast "Update in 5 minutes"`)
2. Take a backup (`ops/bannerfall-backup`) and check that the file is there
3. `git fetch --tags origin && git checkout v1.2.2`, then either pull the image below or build it yourself with `--build-arg VERSION=1.2.2`; set `BANNERFALL_IMAGE` in `.env` to it and start it (`docker compose -f compose.prod.yaml up -d`). Caddy needs no restart
4. Check `bannerfall-admin status` (version 1.2.2) and `bannerfall-admin check`
