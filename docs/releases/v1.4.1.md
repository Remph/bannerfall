A small patch release on top of 1.4.0 with fixes for phones and the reports. The movement lines no longer leave streaks on the map on some phones, "Delete barbarian reports" keeps attacks with nobles and the list rings them in gold, the reports' head fits in one row on desktops, a new start of the game opens the main village, and the More menu's labels sit in the middle of their icons. For hosts there is a new script that updates a world in one command. No database migration and nothing to configure.

## What is fixed and changed

**Map**
- **Streaks on phones:** with the movement lines on, moving or zooming the map quickly could leave red lines on some phones. The dotted and dashed ways are now drawn as whole dots and dashes, and pieces smaller than a pixel are left out. The map looks the same as before and draws a little faster

**Reports**
- **Attacks with nobles stay:** "Delete barbarian reports" keeps the reports of attacks that had nobles in them, as it keeps those with a new banner. The confirmation says so
- **Gold ring:** in the report list, the icon of an attack with nobles has a gold ring around it, in the attacker's and the defender's copy. The icon stays green or red for the result
- **One row on desktops:** from 1024 px the title, the counts and the buttons run in one row across the list and the open report, and the filter chips in the row below, instead of four rows in the list's column. While another filter or page loads, the old page stays on screen, so the open report no longer jumps. Phones are unchanged

**Village**
- **Start on the main village:** a new start of the game opens your main village (the first one in your list). Before, the device kept the village you looked at last for good, which with several villages was often the last one in the list. Within one session the game still remembers the village you are looking at

**Menu**
- **Centred labels:** the labels of the More menu's tiles sit in the middle of their icons (they were 4 px too high)

## For hosts

- **Updating in one command:** `ops/bannerfall-update <version>` (new) does an update's steps in order and stops at the first that fails: it checks the checkout, fetches the tags, pulls the image for exactly that version (or builds it with `--build`), checks the tag out, takes a backup, warns the players in the chat, waits a minute (`--wait`), switches `BANNERFALL_IMAGE` in `.env`, restarts the app, waits for it to be healthy on the new version and runs `bannerfall-admin check`. It shows the plan and asks once (`--yes` skips that). If the new version doesn't come up, it goes back to the old image by itself when no migration ran, and otherwise prints how to restore the backup it took. The README (*Deploying*) has the details, `--help` the options
- **No database migration** (the schema stays at V43) and nothing to configure: no new settings, no new environment variables, no changes to Caddy, `compose.prod.yaml` or `ops/`. Going back to 1.4.0 only needs the old image
- API: report list items carry `summary.nobles` (true when the attack had nobles, in every copy of the battle); `POST /api/reports/delete-barbarian` and the list's `barbarian` count leave out attacks with nobles
- Open pages reload by themselves when the server version changes (since 1.2.1)

## Upgrading a running world (from v1.4.0)

1. `git fetch --tags origin && git checkout v1.4.1`, which brings the new update script along
2. `ops/bannerfall-update 1.4.1` (add `--build` if you build your images on the server). It takes the backup, warns the players, restarts a minute later and checks the new version. Only the app is recreated

Or by hand, as before: announce the update (`bannerfall-admin broadcast "Update in 5 minutes"`), take a backup (`ops/bannerfall-backup`), pull the image below or build it with `--build-arg VERSION=1.4.1`, set `BANNERFALL_IMAGE` in `.env` to it, `docker compose -f compose.prod.yaml up -d`, then check `bannerfall-admin status` (version 1.4.1) and `bannerfall-admin check`.

Going back to 1.4.0 works with the old image and `git checkout v1.4.0`, then `up -d` again.
